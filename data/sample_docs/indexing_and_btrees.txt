A database index is a data structure that speeds up lookups at the cost of extra storage and slower writes. The most common index is the B-Tree, a balanced tree where every leaf sits at the same depth. Because each node holds many keys, a B-Tree over millions of rows is only three or four levels deep, so an equality lookup or range scan touches very few disk pages. A composite index covers several columns and follows the leftmost prefix rule: an index on (course_id, created_at) can serve queries filtering on course_id alone, or on both columns, but not on created_at alone. When a query filters by equality and then sorts by the next index field, the database can return results in index order without an in-memory sort. Too many indexes slow inserts and updates because every index must be maintained, so index only the access patterns you actually run. Use the explain plan to confirm whether a query performs an index scan or a full collection scan.
